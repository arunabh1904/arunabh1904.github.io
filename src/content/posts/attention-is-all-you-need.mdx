## 2017 – Attention Is All You Need

**Paper:** [arXiv:1706.03762](https://arxiv.org/abs/1706.03762) · NeurIPS 2017 · [Reference implementation](https://github.com/tensorflow/tensor2tensor)

## Summary

> The Transformer replaces recurrent sequence processing with self-attention, giving distant tokens short communication paths and allowing parallel computation across training positions. Its encoder–decoder design still generates target tokens autoregressively. The important trade-off is therefore parallel training and direct token interaction against quadratic attention cost, not the elimination of every sequential operation. Translation results and controlled ablations show why multiple heads, sufficient key dimensions, dropout, and the training recipe matter alongside the attention equation.

## Core Insights

### Three attention operations serve different information paths

The source architecture has six encoder layers and six decoder layers. Encoder self-attention lets source positions exchange information. Decoder self-attention sees only the target prefix. Cross-attention then lets the decoder query the encoder's source representations.

Follow the arrows entering the decoder's middle attention block: queries come from the decoder, while keys and values come from the encoder. That is the bridge between the two sequences. The lower decoder block has no such bridge; its causal mask and shifted inputs prevent a prediction from seeing the target token it is meant to produce.

![Original Transformer source architecture with encoder, masked decoder, and cross-attention](/assets/images/attention-is-all-you-need-paper-figure.png)
*Fig 1: The middle decoder attention block reads encoder states through cross-attention. The lower block reads only the target prefix. Feed-forward layers transform each position after information is exchanged. | source: [Transformer, Figure 1](https://arxiv.org/abs/1706.03762)*

The original normalization order is also visible: each sublayer computes $\mathrm{LayerNorm}(x+\mathrm{Sublayer}(x))$. This is post-normalization. It should not be silently replaced in the paper's description with the pre-normalization arrangement used by many later models.

### Attention first chooses positions, then mixes their values

For one head, take queries of shape $[B,T_q,d_k]$, keys $[B,T_k,d_k]$, and values $[B,T_k,d_v]$. The score matrix $QK^\top$ has shape $[B,T_q,T_k]$: each query gets one compatibility score for every key position. Softmax normalizes along the key dimension; multiplying by $V$ produces $[B,T_q,d_v]$.

$$
\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V.
$$

The scaling is about the distribution of logits and gradients. If independent query and key components have zero mean and unit variance, their dot product has variance $d_k$. Dividing by $\sqrt{d_k}$ keeps that variance near one, reducing the tendency for large dimensions to push softmax into nearly saturated choices. This is more specific than saying scaling merely prevents numerical overflow.

![Transformer source Figure 2 showing the complete scaled attention and multi-head computation](/assets/images/transformer-source-figure-2-attention.png)
*Fig 2: The left pipeline forms, scales, and masks compatibility scores before softmax mixes values. The right repeats that computation after learned projections, concatenates head outputs, and projects them back. | source: [Transformer, Figure 2](https://arxiv.org/abs/1706.03762)*

```python
# Attention(Q, K, V) = softmax(Q @ K.T / sqrt(d_k)) @ V
def scaled_dot_product_attention(
    Q: torch.Tensor,
    K: torch.Tensor,
    V: torch.Tensor,
    mask: Optional[torch.Tensor] = None,
    dropout_p: float = 0.0,
) -> Tuple[torch.Tensor, torch.Tensor]:
    d_k = Q.size(-1)
    scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))
    weights = torch.softmax(scores, dim=-1)
    if dropout_p > 0.0:
        weights = torch.nn.functional.dropout(weights, p=dropout_p)
    output = torch.matmul(weights, V)
    return output, weights
```

This compact helper assumes compatible floating-point tensors and at least one allowed key per query. Its mask uses nonzero for allowed positions. Dropout must be passed as zero at inference, because the functional call shown here does not read a module's training state. The returned weights are the weights used in the output, after any dropout.

The playground makes the intermediate scores and weighted values inspectable. Change one query or one key before changing every tensor; that keeps the effect of compatibility separate from the content stored in the values.

### Multiple heads divide a fixed representation budget

The base model uses $d_{model}=512$ with eight heads of dimension 64. Each head has learned query, key, and value projections. Their outputs are concatenated and passed through another learned projection. Heads can therefore express different compatibility patterns while the combined width stays fixed.

The ablation does not support “more heads is always better.” On the English–German development set, one head reaches 24.9 BLEU, eight and 16 reach 25.8, and 32 falls to 25.4. Increasing the head count also reduces each head's dimension in this comparison. Diversity of attention patterns and capacity within each pattern compete for the same budget.

Reducing only the key dimension from 64 to 16 lowers development BLEU to 25.1. Selecting compatible positions is itself a learned representational problem; values cannot recover information that the scoring step consistently routes badly.

### Parallel training does not make generation parallel

During teacher-forced training, all target prefixes are represented in one shifted sequence. The causal mask lets their hidden states be computed together without revealing future targets. During ordinary autoregressive decoding, the next generated token is still needed before the following step can begin.

The paper's complexity table isolates a self-attention layer at $O(n^2d)$ versus a recurrent layer at $O(nd^2)$, with constant versus linear sequential path length across positions. Projection and feed-forward costs remain part of the full Transformer. The favorable attention comparison is especially relevant when sentence length $n$ is smaller than representation width $d$; it does not establish cheap arbitrarily long context.

### Position can be represented without prescribing a recurrent traversal

Self-attention alone does not tell a token where it appears. The model adds positional vectors to token embeddings. Paired sine and cosine channels have different wavelengths, so a relative offset produces a consistent transformation within each frequency pair.

```python
# PE(pos, 2i)   = sin(pos / 10000^(2i / d_model))
# PE(pos, 2i+1) = cos(pos / 10000^(2i / d_model))
def sinusoidal_positional_encoding(
    seq_len: int,
    d_model: int,
    device: Optional[torch.device] = None,
) -> torch.Tensor:
    if device is None:
        device = torch.device("cpu")
    position = torch.arange(seq_len, dtype=torch.float32, device=device).unsqueeze(1)
    div_term = torch.exp(
        torch.arange(0, d_model, 2, dtype=torch.float32, device=device)
        * -(math.log(10000.0) / d_model)
    )
    pe = torch.zeros(seq_len, d_model, device=device)
    pe[:, 0::2] = torch.sin(position * div_term)
    pe[:, 1::2] = torch.cos(position * div_term)
    return pe
```

This helper uses an even model dimension, as in the paper. The position column broadcasts against the frequency row to create a $[T,d_{model}/2]$ phase matrix; alternating columns receive sine and cosine. The resulting $[T,d_{model}]$ encoding can be added across a batch of token embeddings.

Learned positional embeddings reach 25.7 development BLEU versus 25.8 for sinusoids. The authors prefer sinusoids partly because they *may* permit longer-length extrapolation. The translation ablation does not prove reliable extrapolation beyond the training distribution.

### The training recipe changes how the result should be read

The big model reaches 28.4 BLEU on English–German after 3.5 days on eight P100 GPUs; the base trains for about 12 hours. Published comparisons include different architectures and estimated training costs, so they demonstrate a strong practical recipe rather than a perfectly controlled hardware benchmark.

Checkpoint averaging is part of evaluation: five recent checkpoints for the base and 20 for the big model, followed by beam size four and a length penalty. The development ablations omit averaging. Those numbers should not be mixed with the final test scores as if they were the same protocol.

Label smoothing exposes another useful distinction. Removing it improves development perplexity from 4.92 to 4.67 while reducing BLEU from 25.8 to 25.3. A model can become more confident under token likelihood while producing worse translations under the task metric. The arXiv revision 7 PDF gives 41.8 English–French BLEU in Table 2 but 41.0 in Section 6.1. That internal discrepancy prevents treating either number as an unqualified headline result.

## High-Level Takeaways

- Encoder self-attention, causal decoder attention, and cross-attention control three different information paths.
- Scaling dot products limits variance growth and softmax saturation; values are mixed only after positions are scored.
- Multi-head attention allocates a fixed width across patterns, with an empirical cost to both too few and too many heads.
- Training positions can run in parallel while autoregressive generation still proceeds token by token.
- Positional extrapolation is a motivation, while the measured translation gains also depend on regularization and evaluation choices.
